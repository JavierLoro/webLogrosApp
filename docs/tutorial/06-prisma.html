Prisma ORM

Queries tipadas, migraciones automáticas y el schema como fuente de verdad

¿Por qué existe esto?

Escribir SQL a mano desde TypeScript tiene tres problemas serios: primero, los errores de sintaxis SQL solo se detectan en tiempo de ejecución, no cuando escribes el código. Segundo, el resultado de una query es un array de objetos sin tipo: TypeScript no sabe qué campos tiene cada fila. Tercero, gestionar los cambios de esquema de la base de datos a mano (añadir columnas, renombrar tablas…) es propenso a errores y difícil de reproducir en distintos entornos. Prisma resuelve los tres problemas: genera un cliente TypeScript totalmente tipado a partir de tu schema, y gestiona las migraciones automáticamente.

Los tres ficheros clave

Prisma separa su responsabilidad en tres lugares:

FicheroPropósitoQuién lo usa
prisma/schema.prismaDefine los modelos (tablas)Prisma CLI + generator
prisma.config.tsURL de BD para la CLI (migraciones)CLI en tiempo de desarrollo
src/lib/prisma.tsInstancia del cliente para el runtimeTu código Express en producción

El schema — definir los modelos

El schema de Prisma es el centro de todo. Defines los modelos y Prisma se encarga de generar el SQL de las tablas y el cliente TypeScript tipado.

En webLogrosApp

El schema real está en apps/backend/prisma/schema.prisma:

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
}

model Logro {
  id     Int    @id @default(autoincrement())
  nombre String
  puntos Int
}

model User {
  id       Int    @id @default(autoincrement())
  email    String @unique
  password String
}

Cada model es una tabla. @id marca la clave primaria; @default(autoincrement()) equivale a SERIAL en SQL; @unique añade un índice único (el email no puede repetirse).

Migraciones — llevar los cambios a la BD

Una migración es un archivo SQL que describe cómo transformar la base de datos del estado anterior al nuevo. Prisma las genera automáticamente comparando el schema actual con el último estado conocido.

# Crear y aplicar una nueva migración
npx prisma migrate dev --name nombre-descriptivo

# Resetear la BD completamente (solo en desarrollo)
npx prisma migrate reset --force

# Regenerar el cliente TypeScript tras cambiar el schema
npx prisma generate

Los archivos de migración se guardan en prisma/migrations/ y deben subirse a git: son el historial de la estructura de tu base de datos.

Nota Windows: schema-engine bloqueado por antivirus

prisma migrate dev usa un binario nativo llamado schema-engine-windows.exe que Windows Defender o OneDrive pueden bloquear silenciosamente. Si el comando falla o se cuelga en Windows, el workaround es aplicar el SQL directamente al contenedor y regenerar solo el cliente:

# Aplicar el SQL de la migración manualmente
docker exec weblogros_db psql -U admin -d weblogros -c "CREATE TABLE ..."

# Regenerar el cliente sin necesitar el schema engine
npx prisma generate

prisma.config.ts — configurar la CLI

A partir de Prisma 7, la URL de conexión para las operaciones de CLI (migraciones, studio…) se configura en un archivo separado del código de runtime.

En webLogrosApp — prisma.config.ts

El archivo apps/backend/prisma.config.ts tiene este contenido real:

import "dotenv/config";
import { defineConfig } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
  },
  datasource: {
    url: process.env["DATABASE_URL"],
  },
});

dotenv/config carga el apps/backend/.env antes de que Prisma lea DATABASE_URL. Sin esa importación, la variable de entorno sería undefined.

Gotcha: prisma.config.ts fuera de rootDir

Este archivo vive en la raíz del backend, no en src/. Si tsconfig.json tiene "rootDir": "./src", TypeScript intentará compilarlo y fallará con "File 'prisma.config.ts' is not under 'rootDir'". La solución es excluirlo explícitamente:

// tsconfig.json
{
  "compilerOptions": { ... },
  "exclude": ["prisma.config.ts", "node_modules", "dist"]
}

src/lib/prisma.ts — el cliente de runtime

Para las queries desde el código Express se usa una instancia singleton de PrismaClient. En Prisma 7 el cliente runtime necesita un adapter explícito que gestiona la conexión real a la base de datos.

En webLogrosApp — lib/prisma.ts

El archivo real está en apps/backend/src/lib/prisma.ts:

import "dotenv/config"
import { PrismaClient } from "@prisma/client"
import { PrismaPg } from "@prisma/adapter-pg"

const adapter = new PrismaPg({ connectionString: process.env["DATABASE_URL"]! })
const prisma = new PrismaClient({ adapter })

export default prisma

El ! al final de process.env["DATABASE_URL"]! es el operador de aserción no-nula de TypeScript: le dice al compilador "confía en mí, esta variable tiene valor en tiempo de ejecución". Si no estuviera, TypeScript se quejaría porque process.env["DATABASE_URL"] podría ser undefined.

Nota Prisma 7: el adapter es obligatorio

En versiones anteriores de Prisma (5 y 6), el cliente leía DATABASE_URL directamente del entorno sin adapter. En Prisma 7 el adapter es explícito y obligatorio: hay que crear PrismaPg (o el adapter de otro driver) y pasarlo al constructor. Si no, el cliente no sabe cómo conectarse.

Las dependencias necesarias son:

npm install @prisma/client @prisma/adapter-pg pg
npm install --save-dev prisma @types/pg

Queries básicas

El cliente de Prisma ofrece métodos tipados para cada operación CRUD. Los nombres de los métodos son predecibles y el autocompletado del editor funciona sobre ellos:

import prisma from "../lib/prisma"

// Leer todos los logros
const logros = await prisma.logro.findMany()
// → Logro[]  (TypeScript sabe exactamente qué campos tiene cada elemento)

// Leer un logro por id (devuelve null si no existe)
const logro = await prisma.logro.findUnique({ where: { id } })
// → Logro | null

// Crear un logro nuevo
const nuevo = await prisma.logro.create({
  data: { nombre, puntos }
})
// → Logro  (con el id generado por la BD)

// Buscar un usuario por email (campo @unique)
const user = await prisma.user.findUnique({ where: { email } })

// Crear un usuario con contraseña hasheada
const user = await prisma.user.create({
  data: { email, password: hash }
})

Este código aparece en las rutas reales del proyecto. En apps/backend/src/routes/logros.ts:

router.get("/", async (_req: Request, res: Response) => {
  const logros = await prisma.logro.findMany()
  res.json(logros)
})

router.get("/:id", async (req: Request, res: Response) => {
  const id = Number(req.params.id)
  const logro = await prisma.logro.findUnique({ where: { id } })

  if (!logro) {
    res.status(404).json({ error: "Logro no encontrado" })
    return
  }

  res.json(logro)
})
