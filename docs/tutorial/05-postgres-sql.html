PostgreSQL y SQL básico

La base de datos relacional donde viven los datos de forma persistente

¿Por qué existe esto?

Las variables en JavaScript existen en memoria: cuando reinicias el servidor, desaparecen. Para que los logros, usuarios y cualquier dato del proyecto sobrevivan a reinicios y sean accesibles desde varios procesos a la vez, se necesita una base de datos. PostgreSQL es una base de datos relacional: organiza los datos en tablas con filas y columnas, garantiza que los datos sean consistentes y ofrece un lenguaje estándar para consultarlos: SQL.

Conceptos fundamentales

Una base de datos relacional organiza los datos así:

SQL — el lenguaje de las bases de datos

SQL (Structured Query Language) es el lenguaje estándar para hablar con bases de datos relacionales. Tiene cuatro operaciones fundamentales, conocidas como CRUD:

OperaciónSQLEquivalente HTTP
Create (crear)INSERT INTOPOST
Read (leer)SELECTGET
Update (actualizar)UPDATEPUT / PATCH
Delete (borrar)DELETE FROMDELETE

Crear una tabla

CREATE TABLE define la estructura: las columnas, sus tipos y sus restricciones. Una vez creada, la tabla almacena filas que siguen esa estructura.

CREATE TABLE logros (
  id     SERIAL      PRIMARY KEY,   -- número autoincremental único
  nombre VARCHAR(100) NOT NULL,     -- texto de hasta 100 caracteres, obligatorio
  puntos INTEGER      NOT NULL      -- número entero, obligatorio
);

Tipos de dato más comunes en PostgreSQL:

TipoQué almacena
SERIALEntero autoincremental (1, 2, 3…) — perfecto para IDs
INTEGERNúmero entero
VARCHAR(n)Texto de hasta n caracteres
TEXTTexto de longitud ilimitada
BOOLEANVerdadero o falso
TIMESTAMPFecha y hora

Insertar datos

INSERT INTO logros (nombre, puntos)
VALUES ('Primer login', 10);

INSERT INTO logros (nombre, puntos)
VALUES ('Primera tarea completada', 25);

No se especifica id porque es SERIAL: PostgreSQL lo asigna automáticamente.

Consultar datos

-- Todos los logros
SELECT * FROM logros;

-- Solo nombre y puntos, ordenados por puntos descendente
SELECT nombre, puntos FROM logros ORDER BY puntos DESC;

-- Un logro concreto por id
SELECT * FROM logros WHERE id = 1;

-- Logros con más de 20 puntos
SELECT * FROM logros WHERE puntos > 20;

* significa "todas las columnas". WHERE filtra filas. ORDER BY ordena el resultado.

Actualizar y borrar

-- Actualizar los puntos de un logro
UPDATE logros SET puntos = 50 WHERE id = 1;

-- Borrar un logro
DELETE FROM logros WHERE id = 2;

Gotcha: siempre usa WHERE en UPDATE y DELETE

Si ejecutas UPDATE logros SET puntos = 0 sin WHERE, actualizas todas las filas. Si ejecutas DELETE FROM logros sin WHERE, borras toda la tabla. Siempre verifica que tu filtro sea correcto antes de ejecutar estas sentencias.

Acceder a PostgreSQL desde la terminal

El cliente de línea de comandos de PostgreSQL se llama psql. Comandos especiales de psql (empiezan con \, sin punto y coma al final):

\l          -- listar todas las bases de datos
\c weblogros  -- conectarse a la base de datos "weblogros"
\dt         -- listar las tablas de la BD actual
\d logros   -- ver la estructura (columnas y tipos) de la tabla "logros"
\q          -- salir de psql

En webLogrosApp

La base de datos corre en Docker. Para entrar a psql directamente sobre el contenedor:

docker exec -it weblogros_db psql -U admin -d weblogros

Desde ahí puedes inspeccionar los datos que Prisma ha creado con sus migraciones. El contenedor se llama weblogros_db (definido en docker-compose.yml), corre PostgreSQL 16, usuario admin, contraseña admin123, base de datos weblogros, puerto 5432.

Las tablas del proyecto corresponden a los modelos de Prisma: Logro → tabla logros, User → tabla users. En Prisma, por convención, los nombres de modelo en PascalCase se mapean a nombres de tabla en snake_case en plural.

Para ver todos los logros insertados:

SELECT * FROM "Logro";

Nota: mayúsculas en Prisma

Prisma usa el nombre exacto del modelo como nombre de tabla (con mayúscula inicial). En psql, los identificadores con mayúsculas hay que envolverlos en comillas dobles: "Logro", "User".

Relaciones entre tablas

El verdadero poder de las bases de datos relacionales está en conectar tablas entre sí con claves foráneas (foreign keys). Aunque webLogrosApp aún no las usa, este es el patrón que viene en la fase 6:

CREATE TABLE user_logros (
  id        SERIAL PRIMARY KEY,
  user_id   INTEGER NOT NULL REFERENCES users(id),
  logro_id  INTEGER NOT NULL REFERENCES logros(id),
  ganado_en TIMESTAMP DEFAULT NOW()
);

REFERENCES logros(id) es la clave foránea: garantiza que no puedes insertar un logro_id que no exista en la tabla logros. La integridad referencial es una de las garantías que hacen fiables las bases de datos relacionales.
