Next.js

El framework que convierte React en una aplicación web completa, con rutas, servidor y renderizado inteligente.

¿Por qué existe esto?

React es una librería de componentes de UI. Pero una aplicación web real necesita más: rutas (/login, /logros/1), un servidor que sirva las páginas, optimizaciones de rendimiento y una forma de obtener datos antes de mostrar la pantalla. Next.js aporta todo eso encima de React. En lugar de configurar un router, un servidor, un bundler y un sistema de rutas por separado, Next.js los unifica en un solo framework con convenciones claras.

App Router — rutas por archivos

Next.js crea rutas automáticamente según la estructura de carpetas dentro de src/app/. No hay que registrar rutas en código; el sistema de ficheros es el router.

src/app/page.tsx              →  /
src/app/logros/[id]/page.tsx  →  /logros/1, /logros/2, ...
src/app/login/page.tsx        →  /login
src/app/register/page.tsx     →  /register

Cada page.tsx es una página. Los corchetes [id] marcan un segmento dinámico: captura cualquier valor en esa posición de la URL.

Server Components vs Client Components

Esta es la distinción más importante de Next.js App Router. Por defecto, todos los componentes son Server Components: se ejecutan en el servidor, generan HTML y lo envían al navegador. Para interactividad (formularios, eventos, estado) se necesitan Client Components, que se ejecutan en el navegador.

Server Component Client Component
Ejecución Servidor Navegador
useState, useEffect ✗ No disponible ✓
localStorage ✗ No disponible ✓
fetch ✓ Sin CORS (servidor a servidor) ✓ Con CORS (navegador → API)
Directiva (ninguna, por defecto) "use client" al inicio del archivo

¿Cuándo usar Client Component?

  • Formularios (login, registro, crear logro)
  • Cualquier hook: useState, useEffect, useRouter
  • Acceso a localStorage o eventos del DOM
  • Componentes que reaccionan a interacción del usuario

Server Component en la práctica

Un Server Component puede ser una función async que hace fetch directamente, sin useEffect. Los datos están disponibles antes de que el HTML llegue al navegador.

En webLogrosApp

apps/frontend/src/app/page.tsx — la página principal es un Server Component. Hace fetch al backend y pinta la lista de logros sin ningún hook:

async function getLogros(): Promise<Logro[]> {
  const res = await fetch(
    `${process.env.BACKEND_URL ?? "http://localhost:3001"}/logros`,
    { cache: "no-store" }
  )
  return res.json()
}

export default async function Home() {
  const logros = await getLogros()
  return (
    <main className="max-w-2xl mx-auto p-8 flex flex-col gap-8">
      <h1 className="text-3xl font-bold">Logros del equipo</h1>
      <NuevoLogro />
      <ul className="flex flex-col gap-4">
        {logros.map((logro) => (
          <li key={logro.id}>
            <Link href={`/logros/${logro.id}`} ...>
              <span>{logro.nombre}</span>
              <span>{logro.puntos} pts</span>
            </Link>
          </li>
        ))}
      </ul>
    </main>
  )
}

Nota que el fetch usa process.env.BACKEND_URL (variable de servidor) con fallback a http://localhost:3001. Esto funciona en producción (Docker) y en desarrollo.

Gotcha: URLs hardcodeadas en Client Components

En el proyecto actual, apps/frontend/src/app/login/page.tsx y apps/frontend/src/app/components/NuevoLogro.tsx hacen fetch("http://localhost:3001/...") directamente. Esto romperá en producción cuando el frontend corra en un contenedor Docker: localhost:3001 no es el backend, es el mismo contenedor del frontend.

En Client Components no se puede usar process.env.BACKEND_URL (variable de servidor). La solución es usar variables de entorno con prefijo NEXT_PUBLIC_ (se exponen al navegador) o hacer que los Client Components llamen a rutas internas de Next.js (/api/...) que sí pueden hablar con el backend internamente.

Client Component — formulario con estado

La primera línea del archivo debe ser exactamente "use client". Activa todos los hooks de React.

En webLogrosApp

apps/frontend/src/app/login/page.tsx — Client Component con formulario, estado y navegación programática:

"use client"

import { useState } from "react"
import { useRouter } from "next/navigation"

export default function LoginPage() {
  const router = useRouter()
  const [email, setEmail] = useState("")
  const [password, setPassword] = useState("")
  const [error, setError] = useState("")

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault()
    setError("")
    try {
      const res = await fetch("http://localhost:3001/auth/login", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ email, password }),
      })
      if (!res.ok) { setError("Email o contraseña incorrectos"); return }
      const data = await res.json()
      localStorage.setItem("token", data.token)  // guardar token en el navegador
      router.push("/")                            // redirigir al inicio
    } catch (err) {
      setError("No se pudo conectar con el servidor")
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input type="email" value={email} onChange={(e) => setEmail(e.target.value)} />
      <input type="password" value={password} onChange={(e) => setPassword(e.target.value)} />
      {error && <p>{error}</p>}
      <button type="submit">Entrar</button>
    </form>
  )
}

useEffect y usePathname

useEffect ejecuta código después de que el componente se renderiza en el navegador. Es la única forma de acceder a APIs del navegador (como localStorage) desde un componente React, porque el servidor no tiene localStorage.

useEffect(() => {
  // esto solo corre en el navegador
  const token = localStorage.getItem("token")
  setLogueado(!!token)
}, [])  // [] = solo al montar el componente (una vez)

El array de dependencias controla cuándo se re-ejecuta el efecto:

  • [] — solo al montar (una vez)
  • [valor] — cada vez que valor cambia
  • sin array — en cada render (evitar)

usePathname() devuelve la ruta actual. Pasarlo como dependencia de useEffect hace que el efecto se re-ejecute al navegar entre páginas.

En webLogrosApp

apps/frontend/src/app/components/Header.tsx — detecta si el usuario está logueado y se actualiza al navegar. Sin pathname como dependencia, el Header mostraría el estado de sesión desactualizado hasta recargar la página:

"use client"

import { useState, useEffect } from "react"
import { useRouter, usePathname } from "next/navigation"
import Link from "next/link"

export default function Header() {
  const router = useRouter()
  const pathname = usePathname()
  const [logueado, setLogueado] = useState(false)

  useEffect(() => {
    setLogueado(!!localStorage.getItem("token"))
  }, [pathname])  // se re-ejecuta cada vez que cambia la ruta

  function handleLogout() {
    localStorage.removeItem("token")
    router.push("/login")
  }

  return (
    <header>
      <Link href="/">Logros del equipo</Link>
      {logueado
        ? <button onClick={handleLogout}>Cerrar sesión</button>
        : <>
            <Link href="/login">Iniciar sesión</Link>
            <Link href="/register">Registrarse</Link>
          </>
      }
    </header>
  )
}

router.refresh() — refrescar datos del servidor

Después de crear un logro desde un Client Component, la lista (que es un Server Component) sigue mostrando los datos anteriores. router.refresh() le dice a Next.js que vuelva a ejecutar los Server Components de la página y traiga datos frescos, sin cambiar de ruta.

En webLogrosApp

apps/frontend/src/app/components/NuevoLogro.tsx — tras crear un logro con éxito, refresca la lista. El formulario es Client Component ("use client", usa useState y localStorage), pero la lista que se actualiza es el Server Component padre:

async function handleSubmit(e: React.FormEvent) {
  e.preventDefault()
  try {
    const res = await fetch("http://localhost:3001/logros", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${token}`,   // token de localStorage
      },
      body: JSON.stringify({ nombre, puntos: Number(puntos) }),
    })
    if (!res.ok) { setError("Error al crear el logro"); return }
    setNombre("")
    setPuntos("")
    router.refresh()   // recarga la lista del Server Component padre
  } catch (err) {
    setError("No se pudo conectar con el servidor")
  }
}

Mezclar Server y Client Components

Un Server Component puede importar y renderizar un Client Component. El Client Component se "hidrata" en el navegador (React lo convierte en interactivo). Lo importante es que ambos coexisten en la misma página:

// page.tsx (Server Component) — hace fetch sin CORS
export default async function Home() {
  const logros = await getLogros()   // fetch en el servidor
  return (
    <main>
      <NuevoLogro />   {/* Client Component — corre en el navegador */}
      <ul>{logros.map(...)}</ul>
    </main>
  )
}
// NuevoLogro.tsx — Client Component
"use client"

export default function NuevoLogro() {
  const [token, setToken] = useState<string | null>(null)
  // ...
}

Rutas dinámicas

El valor del segmento entre corchetes llega como params. En Next.js App Router, params es una Promise (hay que usar await):

// src/app/logros/[id]/page.tsx
export default async function LogroPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const res = await fetch(`http://localhost:3001/logros/${id}`, { cache: "no-store" })
  const logro = await res.json()
  return <div>{logro.nombre}</div>
}

Componente Link

<Link> de Next.js navega entre páginas sin recargar el navegador completo. Es más rápido que un <a href="..."> normal porque Next.js solo actualiza la parte de la página que cambia.

import Link from "next/link"

// Enlace estático
<Link href="/login">Iniciar sesión</Link>

// Enlace dinámico con template literal
<Link href={`/logros/${logro.id}`}>Ver detalle</Link>

Tailwind CSS

Tailwind reemplaza los archivos CSS separados por clases de utilidad directamente en el JSX. Cada clase hace una sola cosa: text-3xl define el tamaño del texto, font-bold lo pone en negrita, mb-6 añade margen inferior.

<h1 className="text-3xl font-bold mb-6">Logros del equipo</h1>

<span className="font-bold text-blue-600">{logro.puntos} pts</span>

<button className="bg-blue-600 text-white rounded-lg p-2 hover:bg-blue-700 transition-colors">
  Entrar
</button>

cache: "no-store" en Server Components

Por defecto Next.js cachea los resultados de fetch en Server Components. Si creas un logro nuevo pero la caché sigue devolviendo la lista anterior, añade { cache: "no-store" }:

const res = await fetch("http://localhost:3001/logros", { cache: "no-store" })

Así Next.js siempre consulta el backend en lugar de devolver una respuesta guardada.
