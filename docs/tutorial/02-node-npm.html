Node.js y npm

JavaScript fuera del navegador, y el gestor de paquetes que lo alimenta.

Node.js

¿Por qué existe esto?

JavaScript nació encerrado en el navegador. Para escribir un servidor web había que usar otro lenguaje: Python, Ruby, Java… En 2009, Ryan Dahl tomó el motor V8 de Chrome (el que interpreta JavaScript) y lo sacó del navegador para ejecutarlo como proceso independiente en el sistema operativo. Eso es Node.js: el mismo lenguaje que ya conoces, pero corriendo como una aplicación de línea de comandos capaz de abrir sockets, leer archivos y escuchar en un puerto de red. La consecuencia práctica: un solo lenguaje para frontend y backend.

Comandos básicos de Node

node archivo.js       # ejecutar un archivo JavaScript
node --version        # ver qué versión tienes instalada
npm --version         # ver la versión de npm (viene con Node)

npm — el gestor de paquetes

¿Por qué existe esto?

Programar sería insoportable si tuvieras que escribir desde cero cada pieza de funcionalidad: parsear JSON, gestionar fechas, crear servidores HTTP… La comunidad ya resolvió esos problemas y publicó las soluciones como paquetes. npm (Node Package Manager) es el registro y la herramienta de línea de comandos que te permite instalar esos paquetes en segundos. También es el que registra qué paquetes usa tu proyecto (en package.json) para que cualquiera pueda reproducir el entorno exacto con un simple npm install.

Comandos esenciales

npm init -y                        # inicializar proyecto (crea package.json)
npm install express                # instalar paquete de producción
npm install --save-dev nodemon     # instalar paquete solo para desarrollo
npm run dev                        # ejecutar el script "dev" del package.json

package.json — el corazón del proyecto

Registra el nombre del proyecto, sus dependencias y los scripts que puedes ejecutar con npm run. Funciona como un contrato: si otra persona clona tu repositorio y ejecuta npm install, obtendrá exactamente los mismos paquetes.

nodemon — recarga automática en desarrollo

¿Por qué existe esto?

Cuando modificas el código de un servidor Node.js, los cambios no surten efecto hasta que reinicies el proceso a mano (Ctrl+C + node server.js de nuevo). En desarrollo eso se vuelve tedioso muy rápido. nodemon observa los archivos del proyecto y reinicia el servidor automáticamente cada vez que guardas un cambio. Es una herramienta de desarrollo puro: en producción el servidor arranca una vez y no necesita observar archivos.

npm install --save-dev nodemon
npm run dev   # arranca el servidor con nodemon

Gotcha: proceso zombie en el puerto

Al cerrar nodemon con Ctrl+C, a veces el proceso hijo (ts-node) no muere correctamente. La siguiente vez que arrancas npm run dev, nodemon muestra clean exit - waiting for changes before restart y no levanta el servidor. El proceso viejo sigue ocupando el puerto y respondiendo peticiones sin tus últimos cambios.

Diagnóstico:

netstat -ano | grep :3001   # ver qué proceso ocupa el puerto

Solución:

# PowerShell
Stop-Process -Id <PID> -Force

# CMD
taskkill /PID <PID> /F

Después vuelve a lanzar npm run dev. El servidor debería mantenerse activo sin mostrar clean exit.

En webLogrosApp

El script dev del backend combina nodemon con TypeScript. En apps/backend/package.json:

"scripts": {
  "dev": "nodemon --exec ts-node src/server.ts",
  "build": "tsc",
  "postinstall": "prisma generate"
}

nodemon --exec ts-node significa: "en lugar de ejecutar el archivo con node, ejecútalo con ts-node (que entiende TypeScript)". Así el servidor se reinicia automáticamente con cada guardado y no hay que compilar a mano.

Las dependencias de producción del backend son: express, prisma, @prisma/client, bcryptjs, jsonwebtoken, dotenv y pg. Las de desarrollo: nodemon, typescript, ts-node y los paquetes @types/*.
